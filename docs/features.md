# 구현된 기능

현재까지 구현된 기능을 화면 단위 트리로 정리하고, 엣지 케이스에서의 실제 동작을 기록한다. 기능이 추가·변경·제거될 때마다 갱신한다.

> 마지막 업데이트: 2026-10-19 (#17 정지/시작 버튼 위치 변경 반영)

---

## 2. 엣지 케이스 동작

코드 기준으로 확인한 **현재 동작**이다. ⚠️는 의도와 다를 수 있어 개선 검토가 필요한 항목이다.

### 2.1 자정 (날짜 경계)

| 상황 | 현재 동작 |
|------|-----------|
| 앱을 켜 둔 채 자정이 지남 | 자정까지 남은 시간만큼 delay한 뒤 누적 시간·오늘 요약·세션 목록을 **초기화**한다. (#20) |
| 자정에 세션 진행 중 | 진행 중 세션을 **자정에서 끊어 저장**하고, 같은 타입으로 오늘 0시부터 이어서 기록한다. 여러 날에 걸쳐 있으면 날짜마다 나눠 저장한다. (#20) |
| 백그라운드에 있다가 자정 이후 복귀 | 타이머 화면 onResume 시 날짜 변경을 즉시 처리하고 자정 예약을 다시 계산한다. 타입/정지 버튼을 누를 때도 먼저 확인한다. (#20) |
| 정지 후 앱 재시작 시 자정 걸친 세션 | 정지 시점에만 저장되므로, 앱이 계속 살아 있었다면 이미 자정 기준으로 분할되어 있다. 프로세스가 죽어 처리되지 못한 경우는 세션 자체가 유실된다(2.2 참고). |
| 날짜 판정 기준 | 저장: 시스템 기본 시간대로 epoch 초 변환. 히스토리 집계: SQLite `localtime`으로 조회 시점의 시간대 기준. |

### 2.2 백그라운드 · 프로세스 · 생명주기

| 상황 | 현재 동작 |
|------|-----------|
| 세션 진행 중 다른 탭으로 이동 | 타이머 ViewModel이 Activity 스코프라 **유지된다**. 다시 돌아오면 계속 진행 중. |
| 세션 진행 중 홈으로 나감 (백그라운드) | 프로세스가 살아 있는 동안은 유지된다. 경과 시간은 `현재 시각 − 시작 시각`으로 계산하므로 복귀 시 정확하다. 기록 중 알림이 표시된다. (#19) |
| 백그라운드 중 자정 경과 | 세션이 자정에서 분할되고 알림의 크로노미터도 0시 기준으로 다시 시작한다. |
| 알림 권한 거부 | 알림 없이 기존과 동일하게 동작한다. 권한 요청은 기록 시작 시마다 시도하지만, 두 번 거부하면 시스템이 더 묻지 않는다. |
| 화면 회전 등 구성 변경 중 | 백그라운드로 보지 않아 알림이 뜨지 않는다. |
| 백그라운드에서 시스템이 프로세스를 종료 / 최근 앱에서 스와이프 종료 | 세션은 **정지 시점에만 저장**되므로 진행 중이던 세션은 **유실**된다. 재실행 시 대기 상태로 시작. 포그라운드 서비스가 아닌 일반 알림이라 프로세스 보호 효과는 없다. ⚠️ |
| 프로세스 종료 후 남은 알림 | 알림이 남아 크로노미터가 계속 흐를 수 있다. ⚠️ 정지 버튼을 누르면 알림만 지워지고, 앱을 다시 실행하면 시작 시 제거된다. |
| 화면 회전 등 구성 변경 | Activity ViewModel이 유지되므로 세션이 이어진다. |
| 루트 탭에서 뒤로가기 | 백스택이 1개면 내비게이션이 처리하지 않아 시스템 동작을 따른다. Android 12+는 앱이 백그라운드로 이동(세션 유지), Android 11(minSdk 30)은 Activity가 종료되어 **진행 중 세션 유실**. ⚠️ |
| 언어 변경 | 이미 만들어진 세션 목록의 시각 문자열은 이전 로케일 포맷을 유지하고, 새로 만들어지는 값부터 새 로케일이 적용된다. |

### 2.3 시간 · 시계

| 상황 | 현재 동작 |
|------|-----------|
| 기기 시각을 수동 변경 / 서머타임 전환 | 경과 시간을 `LocalDateTime` 차이로 계산하므로 **점프·음수 지속시간**이 생길 수 있다. ⚠️ |
| 시간대 변경 | 저장된 epoch 값은 그대로지만 표시·날짜 집계가 새 시간대 기준으로 바뀌어, 과거 기록의 날짜가 이동할 수 있다. |
| 1초 미만 세션 (빠르게 타입 전환) | 최소 길이 제한 없이 0초 세션도 저장되어 세션 수에 포함된다. ⚠️ |

### 2.4 로그 타입 변경의 소급 효과

| 상황 | 현재 동작 |
|------|-----------|
| 타입의 효율 포함 여부 변경 | 히스토리·상세 집계가 타입의 **현재 값**과 JOIN하므로 **과거 기록의 효율까지 바뀐다**. ⚠️ |
| 타입의 색상·아이콘·이름 변경 | 과거 세션 표시에도 즉시 반영된다. |
| 세션 진행 중 해당 타입 수정 | 타입 목록이 Flow로 갱신되어 버튼에 바로 반영되고, 세션은 계속 진행된다. |
| 마지막으로 기록한 타입 판정 | 앱 시작 시 DB에서 종료 시각이 가장 늦은 세션의 타입, 이후에는 마지막으로 시작한 타입. 날짜와 무관하게 유지된다. |
| 마지막 타입이 목록에 없음 (비활성 등) | 시작 버튼 대신 안내 문구가 표시된다. |
| 앱 재시작 후 정지 상태 화면 | 마지막 타입의 이름·색상과 그 타입의 오늘 누적 시간을 보여준다. 오늘 기록이 없으면 00:00. |
| 자정 경과 | 오늘 누적 시간이 초기화되므로 타이머 카드 시간도 00:00부터 다시 표시된다. 타입 이름·색상은 유지. |
| 비활성(isActive = 0) 타입 | 현재 UI로는 만들 수 없음. 만약 생기면 타이머 요약에서는 빠지지만 히스토리 집계에는 포함되고, 세션 목록에서 이름 없이 회색으로 표시된다. |
| 모든 타입이 없어지는 경우 | DB를 열 때마다 비어 있는지 확인해 기본 타입 2개를 다시 생성한다. 기본 타입 이름은 로케일과 무관하게 한국어. ⚠️ |

### 2.5 집계 계산

| 항목 | 현재 동작 |
|------|-----------|
| 효율 % | 정수 나눗셈으로 소수점 버림 (예: 66.9% → 66%) |
| 휴식만 있는 날 | 효율 0% |
| 히스토리 평균 효율 | 일별 효율의 **단순 평균** (작업 시간 가중 아님). 기간 제한 없이 전체 기록 대상. |
| 총 작업 시간 | 일별 작업 초를 분으로 버림한 뒤 합산 |

## 3. 미구현 기능

- 로그 타입 삭제·숨김 UI (DAO에 `hide`, `delete`는 존재)
- 로그 타입 순서 변경 UI
- 저장된 세션의 수정·삭제
- 진행 중 세션의 영속화 / 포그라운드 서비스 (현재는 일반 알림만 표시)
- DB 마이그레이션 (현재 스키마 변경 시 데이터 초기화)
- 테스트 코드
